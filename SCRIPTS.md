# Command reference

Run from the repository root unless the table says otherwise. Script names come from [package.json](package.json), [web/package.json](web/package.json) and [efsdb/php/core/package.json](efsdb/php/core/package.json); read the referenced implementation before changing an operational target. See [OPERATIONS.md](OPERATIONS.md#tools-and-php-configuration) for PHP setup and [TESTING.md](TESTING.md) for check selection.

## Setup and builds

| Command                                                                                                           | Requirements and source                                                    | Effect / output                                                                                                                                |
| ----------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `bun install --frozen-lockfile`                                                                                   | Bun 1.2.23, root `bun.lock`                                                | Installs workspace dependencies. A lockfile mismatch needs investigation, not an automatic lockfile rewrite.                                   |
| `bun run dev` / `bun run php:serve`                                                                               | PHP with a valid checked-in ini; root package scripts                      | Serves `127.0.0.1:8787` with the PHP router. Requests may initialize/change the selected store. Ctrl+C stops the process and preserves data.   |
| `bun run build:css`                                                                                               | Installed core workspace dependencies; core `tailwind.config.js`           | Writes `efsdb/php/core/public/css/style.css`.                                                                                                  |
| `bun run build:web`                                                                                               | Bun and installed workspaces; [scripts/build-web.ts](scripts/build-web.ts) | Builds CSS plus login, explorer, builder and admin in parallel. Writes shipped CSS/JS and removes obsolete `public/js/efsdb-web.css`.          |
| `bun run build:login`, `build:explorer`, `build:builder`, `build:admin`, `build:window-shell`                     | Root aliases for the corresponding `web:build:*` scripts; app Vite configs | Rebuilds the selected app bundle under `efsdb/php/core/public/js`.                                                                             |
| `bun run web:build:login`, `web:build:explorer`, `web:build:builder`, `web:build:admin`, `web:build:window-shell` | Root wrappers around web workspace scripts                                 | Same selected bundle builds as the aliases above.                                                                                              |
| `bun run --cwd web build:all`                                                                                     | Web workspace dependencies                                                 | Builds all nine web entry points: active apps plus window-shell, notifications, theme, create and prompt. Broader than the default host build. |
| `bun run --cwd web build:notifications`, `build:theme`, `build:create`, `build:prompt`                            | Web workspace scripts and matching app Vite configs                        | Builds a secondary app individually. These commands have no root alias.                                                                        |
| `bun run web:build`                                                                                               | Web TypeScript dependencies                                                | Runs typechecking only; it does not produce app bundles.                                                                                       |

Generated bundles/CSS are tracked deliverables. Keep a recovery copy of existing edited output before rebuilding; review source and output together. Restore only your own accidental changes after checking the expected current hash. Do not discard another worker's generated changes or stage every build artifact automatically.

## Verification entry points

All root PHP scripts below force `efsdb/php/core/php.ini`. If that configuration is not valid locally, use the same PHP entry point with the validated ini selected in [OPERATIONS.md](OPERATIONS.md#tools-and-php-configuration).

| Command                                                                                          | Source / prerequisites                                                                                          | Effects and limits                                                                                                                                                                |
| ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bun run check:api`                                                                              | [apicheck.php](efsdb/php/core/bin/apicheck.php); sodium runtime preflight                                       | Deletes/recreates `.cache/efsdb/tests/core/apicheck-data`, then exercises API behavior.                                                                                           |
| `bun run check:auth`                                                                             | [authcheck.php](efsdb/php/core/bin/authcheck.php); working PHP crypto runtime                                   | Deletes/recreates `.cache/efsdb/tests/core/authcheck-data`.                                                                                                                       |
| `bun run check:conformance:generate`                                                             | [generate.php](efsdb/php/conformance/generate.php)                                                              | Clears `.cache/efsdb/tests/conformance/fixture-generation` and overwrites tracked `spec/fixtures` data. Uses a public test key and random nonces; changed ciphertext is expected. |
| `bun run check:conformance`                                                                      | [run.php](efsdb/php/conformance/run.php); matching fixture set                                                  | Reads fixtures and verifies decryption, reconstructed content and rejection cases. Does not regenerate fixtures.                                                                  |
| `bun run check`                                                                                  | Root command chain                                                                                              | API, auth, fixture generation and conformance in that order. Does not include PHP characterization, web typecheck or browser tests.                                               |
| `bun run web:typecheck`                                                                          | Web workspace TypeScript; `web/tsconfig.json`                                                                   | `tsc --noEmit`; no bundle generation.                                                                                                                                             |
| `bun run web:test:ui`                                                                            | Installed Playwright/Chromium, PHP and Windows PowerShell; [web/playwright.config.ts](web/playwright.config.ts) | Starts a server on 8791, runs `spec/characterization/ui`, writes results/traces. Startup deletes `efsdb/php/core/.cache/playwright-ui-data`. No existing server is reused.        |
| `php -c $efsdbPhpIni spec/characterization/php/StoreUpdateCharacterization.php`                  | Example focused PHP suite; validated ini variable from OPERATIONS                                               | Runs one characterization script using its own disposable store. Inspect the selected script/harness for paths; root `check` does not invoke these scripts.                       |
| `powershell -ExecutionPolicy Bypass -File scripts/php-core.ps1 -l efsdb/php/core/src/Config.php` | Windows PowerShell and PHP; [scripts/php-core.ps1](scripts/php-core.ps1)                                        | Syntax-checks the named file with the checked-in ini. The helper accepts other PHP arguments and has no data isolation of its own.                                                |

Inspect test output paths before cleanup. Do not point the [Playwright launcher](web/scripts/start-playwright-server.ps1) at a live `EFSDB_DATA_DIR`: it recursively deletes its supplied directory. Inspect fixture diffs after `check`; preserve preimages and include regenerated fixtures only when the task calls for that change.

## Maintenance entry points

These commands require an identified target and authorization for their effects. They are not routine checks. All CLI paths below are relative to the repository root and use the PHP configuration selected for that environment.

| Entry point                                            | Effect / recovery concern                                                                                                                                                                                                                                            |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bun run tenant-admin-key`                             | Rotates tenant-admin's login key and prints the new secret. Existing key stops working; avoid captured public logs.                                                                                                                                                  |
| `bun run gc` / [bin/gc.php](efsdb/php/core/bin/gc.php) | Purges expired tombstones, manifests, lookups and chunks in the selected store. Restore requires an appropriate store backup.                                                                                                                                        |
| `bun run reset`                                        | Requires `pwsh`; recursively removes `.cache/efsdb/live/data`, sets it as the data directory, then runs `init`. Back up any wanted data first; this is not a dependency/cache reset.                                                                                 |
| [bin/efsdb.php](efsdb/php/core/bin/efsdb.php)          | `init` imports templates and builds staging/production; `create-user` and `rotate-user-key` mutate identity and print secrets. `dump-logs` can expose operational data. Every command, including `help`, constructs the application and can bootstrap a fresh store. |
| [bin/import.php](efsdb/php/core/bin/import.php)        | Requires `--src` and `--web`; accepts `--root` and delivery options. Defaults to `production`; without `EFSDB_DATA_DIR`, derives a `.efsdb` store beside the web root. Inspect source and destination before importing.                                              |
| [bin/smoke.ps1](efsdb/php/core/bin/smoke.ps1)          | Uses `-Base` and a tenant-admin key; performs authenticated HTTP changes and creates a user. Use a disposable server/store.                                                                                                                                          |
| [scripts/manual](scripts/manual/README.md)             | Recovery, benchmark, import/build and maintenance helpers. In particular `maintenance/sync_prod.php` copies staging to production; read the chosen helper before execution.                                                                                          |

Record the target, operation and evidence without secrets. Cleanup or rollback must be scoped to the outputs owned by the task; never remove all `.cache` content, since the default live store is inside it.
