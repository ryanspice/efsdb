# Command reference

Run from the repository root unless the table says otherwise. Script names come from [package.json](package.json), [web/package.json](web/package.json) and [efsdb/php/core/package.json](efsdb/php/core/package.json); read the referenced implementation before changing an operational target. See [OPERATIONS.md](OPERATIONS.md#tools-and-php-configuration) for PHP setup and [TESTING.md](TESTING.md) for check selection.

## Setup and builds

| Command                                                                                                                              | Requirements and source                                                                             | Effect / output                                                                                                                                                                                             |
| ------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bun install --frozen-lockfile`                                                                                                      | Bun 1.2.23, root `bun.lock`                                                                         | Installs workspace dependencies. A lockfile mismatch needs investigation, not an automatic lockfile rewrite.                                                                                                |
| `bun run dev` / `bun run php:serve`                                                                                                  | Bun and PHP with matching BLAKE3; `scripts/dev.ts` uses the shared launcher | Serves `127.0.0.1:8787` with the PHP router. Requests may initialize/change the selected store. Ctrl+C stops the process and preserves data. |
| `bun run build:css`                                                                                                                  | Installed core workspace dependencies; core `tailwind.config.js`                                    | Writes `efsdb/php/core/public/css/style.css`.                                                                                                                                                               |
| `bun run build:wasm` | Rust 1.93.1, wasm32-unknown-unknown, wasm-pack 0.14.0; [build-wasm.mjs](scripts/ci/build-wasm.mjs) | Locked release build into ignored `web/ui/lib/wasm`; preserves replaced output, target cache and receipts under `.ai/evidence/wasm/`. Run before web checks/builds on a clean checkout or after Rust changes. |
| `bun run build:web`                                                                                                                  | Bun and installed workspaces; [scripts/build-web.ts](scripts/build-web.ts)                          | Builds CSS plus login, explorer, builder, admin and theme in parallel. Writes shipped CSS/JS and removes obsolete `public/js/efsdb-web.css`.                                                                |
| `bun run build:login`, `build:explorer`, `build:builder`, `build:admin`, `build:theme`, `build:window-shell`                         | Root aliases for the corresponding `web:build:*` scripts; app Vite configs                          | Rebuilds the selected app bundle under `efsdb/php/core/public/js`.                                                                                                                                          |
| `bun run web:build:login`, `web:build:explorer`, `web:build:builder`, `web:build:admin`, `web:build:theme`, `web:build:window-shell` | Root wrappers around web workspace scripts                                                          | Same selected bundle builds as the aliases above.                                                                                                                                                           |
| `bun run --cwd web build:all`                                                                                                        | Web workspace dependencies                                                                          | Builds all ten web entry points: login, explorer, builder, admin, admin-dock, window-shell, notifications, theme, create and prompt. Broader than the default host build.                                   |
| `bun run --cwd web build:admin-dock`, `build:notifications`, `build:create`, `build:prompt`                                          | Web workspace scripts and matching app Vite configs                                                 | Builds a secondary app individually. These commands have no root alias.                                                                                                                                     |
| `bun run web:build`                                                                                                                  | Web TypeScript dependencies                                                                         | Runs typechecking only; it does not produce app bundles.                                                                                                                                                    |

Generated bundles/CSS are tracked deliverables. Keep a recovery copy of existing edited output before rebuilding; review source and output together. Restore only your own accidental changes after checking the expected current hash. Do not discard another worker's generated changes or stage every build artifact automatically.

## Verification entry points

Core PHP scripts use [scripts/php-core.ts](scripts/php-core.ts), which resolves the PHP executable and extension/log environment values before loading `efsdb/php/core/php.ini`. It retains a unique module scan file under `.ai/evidence/php-config/run-*`, loads only required modules absent from `php -n`, and passes the same scan path to descendant PHP processes. Its default error log is in that directory. Configure its environment overrides as described in [OPERATIONS.md](OPERATIONS.md#tools-and-php-configuration); the ini assertion requires the checked-in file. The separate `check:runtime` command uses PHP on PATH without an ini.

| Command                                                                                      | Source / prerequisites                                                                                        | Effects and limits                                                                                                                                                                                                                                                                              |
| -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bun run check:runtime`                                                                      | [check-php-runtime.php](scripts/check-php-runtime.php); PHP on PATH                                           | Checks the CLI PHP security-version baseline using `php -n`; no store bootstrap and no serving-runtime acceptance.                                                                                                                                                                              |
| `bun run check:php-ini`                                                                      | [assert_repo_php_ini.php](efsdb/php/core/bin/assert_repo_php_ini.php); configured wrapper                     | Asserts that the repository ini was loaded; does not establish extension ABI or host acceptance.                                                                                                                                                                                                |
| `bun run check:api`                                                                          | [apicheck.php](efsdb/php/core/bin/apicheck.php); sodium runtime preflight                                     | Deletes/recreates `.cache/efsdb/tests/core/apicheck-data`, then exercises API behavior.                                                                                                                                                                                                         |
| `bun run check:auth`                                                                         | [authcheck.php](efsdb/php/core/bin/authcheck.php); working PHP crypto runtime                                 | Deletes/recreates `.cache/efsdb/tests/core/authcheck-data`.                                                                                                                                                                                                                                     |
| `bun run check:conformance:generate`                                                         | [generate.php](efsdb/php/conformance/generate.php)                                                            | Clears `.cache/efsdb/tests/conformance/fixture-generation` and overwrites tracked `spec/fixtures` data. Uses a public test key and random nonces; changed ciphertext is expected.                                                                                                               |
| `bun run check:conformance`                                                                  | [run.php](efsdb/php/conformance/run.php); matching fixture set                                                | Reads fixtures and verifies decryption, reconstructed content and rejection cases. Does not regenerate fixtures.                                                                                                                                                                                |
| `bun run check`                                                                              | Root command chain                                                                                            | Runtime baseline, repository ini, API, auth, fixture generation and conformance in that order; stops at the first failure. Does not include PHP characterization, Rust parity, web typecheck or browser tests.                                                                                  |
| `bun run web:typecheck`                                                                      | Web workspace TypeScript; `web/tsconfig.json`                                                                 | `tsc --noEmit`; no bundle generation.                                                                                                                                                                                                                                                           |
| `bun run web:test:ui`                                                                        | Installed Playwright/Chromium, Node 24+ and PHP with BLAKE3; [web/playwright.config.ts](web/playwright.config.ts) | Starts a server on 8791, runs `spec/characterization/ui`, and writes reports/results under `.ai/evidence/playwright/`. The Node launcher creates a fresh `run-*/data` store and overrides inherited `EFSDB_DATA_DIR`; it does not delete that supplied directory. No existing server is reused. |
| `bun run ./scripts/php-core.ts -- spec/characterization/php/StoreUpdateCharacterization.php` | Example focused PHP suite; configured wrapper                                                                 | Runs one characterization script using its own disposable store. Inspect the selected script/harness for paths; root `check` does not invoke these scripts.                                                                                                                                     |
| `bun run ./scripts/php-core.ts -- -l efsdb/php/core/src/Config.php`                          | Bun, PHP and configured wrapper                                                                               | Syntax-checks the named file with the checked-in ini. The wrapper accepts other PHP arguments and has no data isolation of its own.                                                                                                                                                             |
| `cargo test --locked --manifest-path efsdb-core/Cargo.toml`                                  | Rust toolchain and checked-in Cargo lockfile                                                                  | Builds and tests the Rust implementation; separate from the root PHP `check` chain.                                                                                                                                                                                                             |

Inspect test output paths before cleanup. The active [Playwright launcher](web/scripts/start-playwright-server.mjs) retains its synthetic store and log beneath `.ai/evidence/playwright/run-*`. The older PowerShell launcher remains a separate manual helper with destructive data-directory behavior; it is not the active Playwright path. Inspect fixture diffs after `check`; preserve preimages and include regenerated fixtures only when the task calls for that change.

## Maintenance entry points

These commands require an identified target and authorization for their effects. They are not routine checks. All CLI paths below are relative to the repository root and use the PHP configuration selected for that environment.

| Entry point                                            | Effect / recovery concern                                                                                                                                                                                                                                            |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bun run tenant-admin-key`                             | Rotates tenant-admin's login key and prints the new secret. Existing key stops working; avoid captured public logs.                                                                                                                                                  |
| `bun run gc` / [bin/gc.php](efsdb/php/core/bin/gc.php) | Purges expired tombstones, manifests, lookups and chunks in the selected store. Restore requires an appropriate store backup.                                                                                                                                        |
| `bun run reset`                                        | Requires `pwsh`; recursively removes `.cache/efsdb/live/data`, sets it as the data directory, then runs `init`. Back up any wanted data first; this is not a dependency/cache reset.                                                                                 |
| [bin/efsdb.php](efsdb/php/core/bin/efsdb.php)          | `init` imports templates and builds staging/production; `create-user` and `rotate-user-key` mutate identity and print secrets. `dump-logs` can expose operational data. Every command, including `help`, constructs the application and can bootstrap a fresh store. |
| [bin/import.php](efsdb/php/core/bin/import.php)        | Requires `--src` and `--web`; accepts `--root` and delivery options. Defaults to `production`; without `EFSDB_DATA_DIR`, derives a `.efsdb` store beside the web root. Inspect source and destination before importing.                                              |
| [bin/smoke.ps1](efsdb/php/core/bin/smoke.ps1)          | Uses `-Base` and a tenant-admin key; performs authenticated HTTP changes and creates a user. Use a disposable server/store.                                                                                                                                          |
| [scripts/manual](scripts/manual/README.md)             | Recovery, benchmark, import/build and maintenance helpers. In particular `maintenance/sync_prod.php` copies staging to production; read the chosen helper before execution.                                                                                          |

Record the target, operation and evidence without secrets. Cleanup or rollback must be scoped to the outputs owned by the task; never remove all `.cache` content, since the default live store is inside it.
